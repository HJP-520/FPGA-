# SC520 JTAG 板上回读结果（2026-10-05）

已按用户授权下载 JTAG 调试位流到 SRAM，并使用 TD 6.2.1 ChipWatcher 读取六组板上探针。未写 QSPI Flash。位流 SHA256 为 `94a0cf81189efa4046f0246d2e8eeb50a57fa080ef20563bcef68795fc03efc9`。

| 项目 | 实测结果 | 解读 |
|---|---|---|
| FPGA AE / AG 控制值 | 1991 / 80 | AE 已达本工程上限；AG 为增益表 4×档，非传感器寄存器重新读回值 |
| 传感器 ID | 0xEE4B | 已有 ID 读取结果有效 |
| 摄像头状态 | 0b11011 | 配置完成、AE 事务完成、ID 正确；I²C 历史错误位为 1 |
| AWB R / B | 67065 / 71133（Q16） | 约 1.02333× / 1.08540× |
| AWB 合格样本 / 总拍数 | 230400 / 230400 | 本次捕获时的累计值，不能代替所有帧统计 |
| DDR 状态 | 0b110 | 校准完成、用户接口 ready；该拍不在写忙 |
| MIPI | 帧尾计数 57304，当前行 157；标志 0b1000 | 最近完成帧的行数、长度、通道错误位均为 0 |
| 写 FIFO | 溢出计数 0，本帧/上一帧溢出 0 | 当前证据未见写溢出 |
| 显示读 FIFO | 读空计数 1，损坏帧置黑 0 | 两次完成采样计数均为 1；不能判定那次事件的发生原因 |
| 用户画面反馈 | 有画面，仍然偏暗 | 实时回读通过；画质/亮度尚未通过 |

摄像头原始波形在 `jtag_live/camera_capture.csv`，解码在 `camera_snapshot.json`。其余组保存 UI 波形数值的原始 accessibility 文本及 `ui_captures.json`。其中时间是电脑取证时间，不是 FPGA 精确触发时间；六组分属不同钟域，不是原子快照。

`uics520_cfg/uicfgcs520.v` 在 `iic_bus_error` 为 1 时置位 `O_iic_error`，仅复位清零，因此它不能证明当前每一笔事务都失败。`O_ae_cfg_done` 表示事务序列走完，也不是所有寄存器写成功的逐项 ACK 证明。当前调试版没有通用传感器寄存器回读接口。

亮度排查：KEY4 每次增加 AG 1，按住每约128ms重复；从80到112约需4秒，可对比4×与8×档。KEY3可减回。短按只用于确认控制值响应，通常不足以明显改变画面。后续应确认曝光/增益寄存器实际写入和事务错误位置，再根据图像中间调判断是否启用 Gamma。当前通路中的 `axis_gamma_rgb96` 仅定义，尚未例化。

已有 hwserver 时，ChipWatcher 使用 **AL-LINK-FT(Remote)，127.0.0.1:5555**。探针通过绿色加号加入，Instant Trigger 完成后返回 Idle 才读取新值；Wait for trigger 期间仍显示上一次波形。Continue Trigger 用于连续刷新当前实例，卡在等待时可停止重试，不能把旧值当成新采样。
