## 实际修复

1. **重排缓存**：此前计数相位在空拍保持，但缓存每拍仍覆盖。现在相位和缓存仅在有效拍推进，加入异步复位。
   测试主动改变空拍数据，覆盖四相位复位、真实无空拍帧边界、连续行和字节流对拍。
2. **AWB 帧边界统计**：帧首、坏帧标志与像素一起延迟一拍采集，计入帧首有效样本，保留紧邻下一帧的最后一个样本。
   将合格亮度样本数 `stat_beats` 与总拍数 `frame_beats_total` 分离；720p 默认总拍数上限 230720，超过则拒绝。
   总计数饱和到上限+1，避免长时间漏 SOF 后计数回绕；统计样本仍要求大于 20480、45 < RGB和 < 720、上一帧错误标志为零。
   该保护不是独立的完整帧认证；仍结合已有 MIPI 行长/行数/lane 检测。
3. **抽样与行尾**：每帧轮换四个像素中的抽样相位。AWB 行尾按输出有效拍计数重建，不再把 valid 的任意下降沿当行尾。
4. **FIFO 异常恢复**：摄像头写满时置位本帧错误、丢弃剩余输入；下一帧同步复位后恢复。
   错误状态以稳定电平经两级同步进入 DDR 域，坏帧不推进写指针，也不更新显示读指针。
   显示读空后停止非法 FIFO 读请求，将剩余活动画面置黑，在下一次反相 VSYNC 上升沿恢复；加入饱和事件计数。
   恢复使用边沿而非电平，因为该反相信号在活动画面期间持续为高；相应测试已覆盖这个实际极性。
   这是既有回退机制的加强，未改造成 EOF 后原子提交的完整帧缓存状态机。
5. **曝光/增益**：集中在顶层参数 `STARTUP_AE`、`STARTUP_AG`；饱和度和 AWB 开关集中为 `SAT_K_Q4`、`AWB_ENABLE`。
   I²C 分组写入时锁存曝光/增益，防止操作按键期间同一组寄存器使用不同参数。
6. **流接口约定**：固定视频链明确令下游 ready=1、tdest=0；未实现通用 AXI 背压。
   保留已有提前帧复位脉冲语义，确保 FIFO 先复位再接收像素；它不是与第一个有效字同时出现的标准 AXI SOF。
7. **维护工具**：新增独立验证入口、隔离构建脚本、位流 SHA256 与源码哈希清单、中心/四角统计工具。
   新烧录脚本检查返回码与芯片验证/100% 日志，硬件下载路径尚未实测。原脚本保持旧版本行为。

## 复现

在本目录用 Python 3.10+ 执行（验证本身仅用标准库和 ModelSim）：

```powershell
python .\run_validation.py
```

默认 ModelSim 为 `D:/ModelSim/win64`，可通过环境变量 `MODELSIM_BIN` 修改。
验证只使用本包的实际 RTL 与 `support/` 模型，不读取 `D:/fpga-ptz-tracker`。
原 `03_simulation_optional` 的历史脚本仍保留原外部依赖；新的当前源码验证使用本目录入口。

隔离重建（不会覆盖厂商留档 Runs；需现有 TD 授权）：

```powershell
python .\build_profile.py --profile main
python .\build_profile.py --profile sat_bypass
python .\build_profile.py --profile unity
```

`sat_bypass` 是可重建的第三个对照配置：保留 AWB、仅令 K=16，本次没有生成该 bit。
主版与 unity 同时改变 AWB 和饱和度，二者画面对比不能单独归因到其中一级。
默认 TD 为 `D:/TD6.2.1`，可用 `--td` 指定目录；只有新产物和非负时序裕量满足时才发布 bit。

## 中心泛绿如何继续定位

先比较旧版、主版与 unity：固定场景、光照和曝光，记录高光细节与中心绿色区域。
unity 仍有中心泛绿，说明这两级颜色增强不足以解释现象，还需检查均匀照明、光学/传感器空间色偏和显示/采集链路。
使用均匀照明的中性灰/白目标，避免高光削顶；优先导出摄像头帧，拍显示器的照片会混入显示器和拍照设备的色差。

```powershell
python .\flat_field_stats.py 实拍图.png --output flat_field_stats.json
```

工具需要 Pillow、NumPy，报告中心与四角 RGB 均值、G/R、G/B、可用像素数和接近削顶比例。
只有获得标定数据后再确定空间补偿系数；此次未添加未经标定的 LSC/CCM，也未声称已解决绿心。
降低增益/饱和度也不能恢复传感器采集时已经削顶的细节，实际改善需上板确认。
