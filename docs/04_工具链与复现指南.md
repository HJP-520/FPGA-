## 二、主线 A：烧录出图（5 分钟）

```bat
cd 01_board_burnpack\01_bitstream_flash_direct
burn_camera_sram.bat
```

脚本内部流程：`确认/启动 hwserver.exe`（端口 5555，**必须带 `-r` 参数**）
→ `bw_commands_prompt.exe` 执行 `connect_cable -host_name 127.0.0.1:5555 -open`
→ `download -bit <路径>`。

**实测基线**：识别 `PH1P35MDG324` → 下载 **100% / 11.9 秒** → 出图。

日志里可能出现 `Error @ mpsse.cpp: usb_open() failed` —— 那是 bw 退出时重复拉起 hwserver
的噪声，**无害**。看到 `PRG-2014 : Chip validation success` 和进度条到 100% 即成功。

### 前置条件

- FT2232 **A 通道**必须装 WinUSB 驱动（厂商 `UsbDriverTool.exe`，右键
  `USB Serial Converter A` 0403/6042/Interface 00，**管理员权限**）。B 通道只是 UART，与 JTAG 无关。
- 下载器插在 **USB-JTAG 口**（不是电源口）。
- 未装驱动会报 `PRG-9505 USB device open error`。

### GUI 路线

TD → **Tools → BitWriter** → Debug Server 选 `AL-LINK-FT(Local Host)`
→ Cable `0:123456789` → File Selection **Add** 选 `.bit` → Mode `PROGRAM_SRAM` → **Run**。

### QSPI 固化（赛场"无 PC 参与"要求）

1. 用 QSPI 镜像（库内已有 `camera_to_dsi_display_qspi_16M.bin`，
   或用 BitWriter 的 **Create Flash File** 现场从 `.bit` 生成）；
2. Mode Selection 选 **`PROGRAM_SPI`**（目标是板载 QSPI Flash，不是 FPGA SRAM）；
3. 烧写完成 → **断电** → **拔下载器** → **重新上电**；
4. 验收：**15 秒内出图**；再试"拔掉电脑，只留显示器与板子"仍出图 = 达标。

板载 Flash 为兆易 **W25Q128（16MB）**。

## 三、主线 B：仿真回归

```bash
cd 02_ptz_tracker_dev/tools
python gen_vectors.py        # 必须先跑：生成 *.hex 测试向量
python run_all.py            # 全量 18 项，约 4 分钟
python run_all.py tb_vision_top tb_closed_loop    # 只跑指定项
```

期望输出 `汇总: N/N PASS`；`tb_closed_loop` 期望 `LOCKED: settle_frame=NN`。

### 关键纪律

1. **`tools/golden_model.py` 是算术真值来源。** 改算术**先改 golden_model，再同步 RTL**，
   最后记迭代。倒过来做必然失配。
2. **改完必须跑全量回归**，不跑等于没改完。
3. **禁止臆造"看起来等价"的写法** —— 定点移位、边界策略、取整方向都是位精确约定的一部分。
4. **工程目录必须 ASCII** —— ModelSim 遇中文路径报 sqlite 错误。
5. **接口变更走 `06_interfaces/current/`**（唯一生效版），带变更记录。

### burnpack 侧的独立验证

```powershell
cd 01_board_burnpack\04_codex_validation
python .\run_validation.py          # 当前源码独立验证（不依赖 ptz-tracker）
python .\build_profile.py --profile balanced     # 隔离重建，不覆盖厂商留档
```

ModelSim 路径可用环境变量 `MODELSIM_BIN` 覆盖，默认 `D:/ModelSim/win64`。

厂商 `.al` 在 TD 6.2.1 GUI 打不开（`PRJ-8641`），但**命令行两段式流程可用**：

两段目录里厂商自带 `settings.cfg` / `run.bat`，无需 GUI、无需打开 `.al`。

### 官方 TD 流程

```
read_design → opt_rtl → opt_gate → opt_place → opt_route → bitgen

read_design : elaborate -top <top>; read_sdc; export_db <prj>_elaborate.db
opt_rtl     : insert_debugger; optimize_rtl; report_area; export_db <prj>_rtl.db
opt_gate    : optimize_gate; legalize_phy_inst; update_timing; report_timing_summary
opt_place   : place; update_timing -mode manhattan; report_timing_summary
opt_route   : route; update_timing -mode final; report_timing_summary
bitgen      : bitgen -bit <prj>.bit; export_bitgen_param -file .bitgen_param.f
```

阶段完成标志 `.$step.end.f`，失败标志 `.$step.error.f`。

### GUI 新建工程路线（需要改代码时）

1. 把 `02_TD_project_rebuild/lab_ex1/` 拷到**英文路径**下；
2. TD 6.2.1 → **File → New Project**：器件 `PH1P35MDG324`，速度等级 **-3**；
3. 按厂商 `.al` 的列表添加源码：
   - `user_source/hdl_source/` 整树（96 个 `.v` + 4 个 `.sv` + 12 个 `.vh`）；
   - `user_source/ip_source/`（blk_mem_gen / divider / MCU 等，53 个文件）；
   - 约束 `user_source/constraints_source/pin.adc` 与 `timing.sdc`；
   - 顶层设为 **`design_top_wrapper`**；
4. 跑完整流程 → 产出新 `.bit` → 回到主线 A 烧录。

> **红线**：
> - `td_project/camera_to_dsi_display_Runs/` 里是厂商成功结果的留档（含 `best_result/readMe.txt`），
>   **不要删** —— 那是"厂商成功过"的证据基线。

## 五、故障速查

| 症状 | 原因 | 处置 |
|---|---|---|
| 完全黑屏 | 摄像头 I²C 未配置完成 | 抓 SCL/SDA；传感器 ID 应读到 `EE4B`/`9E4B`；查排线方向与 `O_cam_rst`/`O_cam_24m` |
| 有数据无帧同步 | demosaic 的 tuser 链 | 见嵌入式教程（一）第 5 节"界碑"复盘 |
| 图像花屏/错位 | DDR 帧缓存 | 确认没改分辨率连锁配置；查 DDR 供电与复位时序 |
| 颜色发灰 | 原版链路只有 demosaic+AWB，无 CCM/饱和度 | 烧饱和度增强版（结构性缺失，非参数问题） |
| 反复 `PRG-8000 Connect server failed` | 5555 端口无服务 | `netstat` 查 5555；手动启 hwserver **必须带 `-r`** |
| `PRG-9505 USB device open error` | WinUSB 未装好 | 厂商 `UsbDriverTool.exe`，管理员权限 |
| HDMI 无信号 | 显示器/TMDS | 先烧彩条自检 bit 隔离问题 |
| 上电 15 秒无图，重上电有 | 上电时序 | 按"先显示器和摄像头、后主电源"顺序 |
| `PRJ-8641 XML tag Project is invalid` | 厂商 `.al` 与 TD 6.2.1 不兼容 | **不影响成品 .bit**；重编译走新建工程或命令行两段式 |
| ModelSim 报 sqlite 错 | 工程目录含中文 | 目录改 ASCII |

## 六、JTAG 在线调试（2026-10-05 已验证）

已有 hwserver 时，ChipWatcher 使用 **`AL-LINK-FT(Remote)，127.0.0.1:5555`**。

- 探针通过**绿色加号**加入；
- **Instant Trigger** 完成后返回 **Idle** 才读取新值；
- **Wait for trigger** 期间仍显示上一次波形 —— 不能把旧值当新采样；
- Continue Trigger 用于连续刷新当前实例，卡在等待时可停止重试。

准备与解码脚本见 `01_board_burnpack/04_codex_validation/`：
`prepare_jtag_debug.py` / `export_jtag_debug.py` / `decode_debug_csv.py`。

> **读数解读的坑**：`uics520_cfg/uicfgcs520.v` 的 `O_iic_error` 在 `iic_bus_error` 为 1 时置位、
> 仅复位清零，**不能证明当前每笔事务都失败**；`O_ae_cfg_done` 表示事务序列走完，
> 也不是所有寄存器写成功的逐项 ACK 证明。当前调试版**没有通用传感器寄存器回读接口**。
