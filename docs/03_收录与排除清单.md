# 收录与排除清单

整合时**没有删除或修改任何本地文件**，只在仓库里做筛选收录。
本文件说明筛选规则和每一类被排除内容的去向，避免"仓库里少了东西"变成悬案。

---

## 一、为什么要筛

三个源目录合计约 **3.9 GB**，GitHub 的限制是：

- **单文件硬上限 100 MB** —— 超过直接拒绝推送；
- 仓库总体积建议 **< 1 GB**，超过会出现克隆缓慢、GitHub 提示；
- 单次推送过大容易中断。

源目录里有大量**厂商原始压缩包**和**可重新生成的工具链产物**，占了 3.9 GB 中的绝大部分。
这些既超限、又对版本管理没有价值 —— 它们有明确的官方下载渠道，且版本固定不变。

筛选后入库 **≈ 103 MB / 1 372 文件**，全部是源码、文档、位流与验证证据。

### 3.2 可重新生成的工具链产物（约 700 MB）

| 类别 | 说明 | 如何重新生成 |
|---|---|---|
| `*.db`（约 350 MB） | TD 综合/布局布线数据库 | 重跑 TD 流程（`read_design` → … → `bitgen`） |
| `*_Runs/`、`lab_ex1_build/`、`work_build/` | 布局布线运行目录与构建工作区 | 同上 |
| `*.timing`、`*.timingsummary` | 时序数据库 | 同上；**可读的 `.rpt` 已保留** |
| `*.qdb`、`*.wlf`、`*.logw`、`transcript` | ModelSim 工作库与波形日志 | 重跑仿真 |
| `*.hex`（> 1MB，约 193 MB） | 逐像素/逐拍展开的测试向量 | `python tools/gen_vectors.py` |
| LaTeX 中间产物（`*.aux/*.fls/*.out/*.toc/*.xdv`） | 编译中间态 | `latexmk -xelatex` |

> **注意**：`tools/gen_vectors.py` **必须在跑回归前先执行**，否则缺少 `*.hex`。
> 见 [`../README.md`](../README.md) 第五节。

### 3.3 重复内容

- **15 个比特流按 sha256 去重**：厂商例程工程在不同目录有多份完全相同的 `.bit`
  （`camera_to_dsi_display.bit` 在 `01_video_passthrough`、`lab_ex1_build`、
  `02_TD_project_rebuild` 中各有一份，字节完全一致），只保留一份。
- **`_sc520_src/`**（252 MB）：SC520 官方例程与数据手册的解压副本。
  其中的 lab_ex1 已以更新形态收录于 burnpack 的 TD 工程，数据手册 PDF 收录于
  `03_official_refs`，因此整个目录排除。
- **仓库原有 `官方文件/`**：内容与 `03_official_refs/` 完全重复（md5 一致），已合并去重。
  唯一例外是 `HX1P35安装驱动文档.zip`（1.2 MB），已移入 `03_official_refs/官方资料文档/` 保留。

### 3.4 缓存与依赖

`__pycache__/`、`node_modules/`（含 134 个 js 文件）、`*.pyc`、编辑器配置、系统文件。

## 五、本地文件与仓库的关系

- **本地三个目录未做任何删改**，仍是完整的工作现场。
- 仓库是**筛选后的对外视图**，不含可再生中间产物。
- 需要入库某个被排除的文件时，按本文件的规则判断：是厂商包就别入（走官方渠道），
  是工具链产物就重新生成。
