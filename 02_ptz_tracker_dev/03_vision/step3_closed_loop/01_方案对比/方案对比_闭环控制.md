# 方案对比 —— Step3 闭环控制

日期：2026-09-19 ｜ 状态：已定稿并实现（含闭环在环仿真整定记录）

## 决策 1：控制律 —— 纯 P（选定） vs PD vs PID

**选定**：P + 死区 + 限速 + 限幅。PID 文档（赛题环境清单 5.2）与《基于 FPGA 的云台
追踪系统》一致：闭环延迟 = 采集+检测+输出+舵机机械 ≈ 数十 ms，微分项只会放大噪声。
KD 参数位保留（=0），现场若需可开。I 项不做（死区+限幅已消稳态裕度问题，且目标
跟踪场景无恒值扰动）。

## 决策 2：增益整定 —— **闭环在环仿真**（本项目最有价值的发现）

手算增益（Kp=90，Q8.8≈0.352µs/px）看似温和，但**回路增益**：
```
L = Kp[µs/px] × 舵机[°/µs] × 光学[px/°] × 帧延迟因子
  = 0.352 × 0.18 × 20.6 × ~2(检测/执行延迟)
  ≈ 2.6  →  离散系统发散（闭环仿真实测：θ 单调跑飞至 109°）
```
经两轮整定：**Kp_X=20 (0.156), Kp_Y=18, SLEW=100µs/帧** → 有效回路增益 ≈0.58，
tb_closed_loop 实测 **12 帧（0.2s）锁定并保持**（T1 控制节拍修正后；修正前 36 帧），无极限环。

**方法论沉淀**：舵机+光学的参数化模型（1.5°/帧速率限幅 + 0.18°/µs + 20px/°）放进
TB 与真实 RTL 对跑，是发现这类问题的唯一低成本手段——上板调参一次要几分钟，
仿真一次 40 秒。现场整定仍需复测（真实舵机死区/回差与模型不同），但初值已保证
"上电即稳定"（固化要求）。

## 决策 3：丢失目标策略 —— 保持 vs 回中 vs 扫描

**选定**：保持当前脉宽 + lost_cnt 累加 + OSD 显示 LOST。
理由：评委演示时目标短暂遮挡，保持不动最稳；回中会"找不着北"，扫描显得失控。
`I_track_en=0` 提供手动回中（安全开关），固化默认 track_en=1。

## 决策 4：PWM 结构 —— 单计数器双比较（选定） vs 双计数器

**选定**：单 1,000,000 拍周期计数器 + 两路独立脉宽比较。
共周期是硬要求（《环境清单》5.2：两路异周期会互相拉扯）。上电默认中位 1500µs。
第二道限幅（500~2500）与 gimbal 的软限位（700~2300）双保险。

## 决策 5：无符号陷阱（工程教训）

TB 云台模型首版用 `(duty_x - 13'd1500)`（无符号减法），duty<1500 时回绕成 +7392，
闭环仿真出现"θ 永远正向跑飞"的诡异现象。Verilog 中**所有误差/增量运算必须显式
$signed**。RTL 侧 gimbal_ctrl 全程 signed 检查通过；此教训写入技术文档。
